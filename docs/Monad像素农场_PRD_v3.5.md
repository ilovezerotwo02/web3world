## 0. v3.5 版本结论

v3.5 以方案 A 的结果导向逻辑为产品骨架，以方案 B 的陪伴式表达为体验层。系统必须证明用户完成了什么，界面同时避免把学习包装成紧张、惩罚性的考试。

### 0.1 本版本冻结的产品决策

- 平台只有两个角色：用户、系统管理员。
- Agent 是学习与验证服务，不是平台角色。
- 系统管理员面板只负责平台稳定、异常诊断和状态修复。
- MVP 不接入 Moss，不实现 Kuru Swap、aPriori 质押和沙盘资产预置。
- 课程顺序固定为：Web3 通识 → Monad 基础 → 智能合约。
- 用户开启课程后立即获得对应种子。
- 用户主动开荒和播种后进入学习。
- 完成理论对应发芽，完成章节挑战对应开花。
- Agent 标准化提问或结课小测通过对应结果。
- 用户主动收获后获得果实、平台成就和 NFT 领取资格。
- NFT 是可选的链上学习纪念，不是完成课程的必要条件。
- 每章必须全部答对，但允许立即重试，不清空已完成进度。
- 默认推荐 Agent 对话验证，同时提供地位平等的结课小测入口。
- 一般答错使用陪伴式反馈；私钥、签名、授权和资产风险内容切换为严肃表达。
- 黑客松 MVP 每门课程固定 3 章；完整课程扩展为 6 章时沿用同一难度曲线。
- 修复温室、自由种田、钓鱼、天气、体力和完整经营系统不进入 MVP。

### 0.2 A+B 的职责边界

| 层级 | 采用方向 | 具体内容 |
|---|---|---|
| 产品骨架 | 方案 A | 状态机、难度曲线、全对规则、最终验证、结果动画、验收标准 |
| 用户体验 | 方案 B | NPC 语言、答错提示、Agent 语气、成长反馈、收获回顾 |
| 安全教育 | 结果优先 | 私钥、助记词、签名、授权与资产风险使用明确严肃的警示 |
| 成就表达 | 双层表达 | 系统记录可验证学习结果；用户界面强调成长纪念和个人经历 |
| 长期留存 | 分阶段实现 | MVP 支持回看与复习；自由经营只进入后续路线，不作为当前承诺 |

> **产品公式**：学习结果必须可验证，学习过程可以很温柔。

## 1. 产品概述

### 1.1 产品定位

- **品类**：面向 Web3 新人的游戏化学习平台。
- **首发主题**：Web3 通识、Monad 基础、智能合约。
- **表现形式**：原创治愈系像素农场。
- **核心机制**：学习进度直接驱动作物成长。
- **核心结果**：形成可回看、可验证、可选择上链的学习记录。
- **产品差异**：不是在农场旁边放课程，而是让课程完成本身成为种植过程。

### 1.2 目标用户

主要用户：

- 第一次接触 Web3 的学习者。
- 知道钱包但不理解地址、签名、交易和合约关系的用户。
- 想了解 Monad，但不知道学习顺序的用户。
- 害怕误操作、资产风险和复杂术语的用户。
- 喜欢轻量游戏化反馈、不适应传统课程压力的用户。

### 1.3 用户问题

- Web3 知识分散，缺少清晰的先后顺序。
- 概念学习与真实使用场景脱节。
- 普通课程完成反馈弱，用户看完后不知道自己是否真正掌握。
- 传统考试容易制造压力，答错后缺少继续尝试的动力。
- 课程完成后缺少可以保存、回看和分享的结果。
- 新人对私钥、签名、授权和网络切换缺少安全判断。

### 1.4 产品价值

| 价值 | 用户感受 | 产品实现 |
|---|---|---|
| 路径清楚 | 知道先学什么、后学什么 | 三门课程线性解锁 |
| 进度可见 | 每完成一步都能看到变化 | 种子、发芽、开花、结果、收获 |
| 学习可验证 | 不只是看完，而是能解释和判断 | 章节挑战 + Agent/小测 |
| 答错可恢复 | 不害怕尝试 | 行内解释、知识卡、Agent、立即重试 |
| 结果可保存 | 学习过程留下纪念 | 果实、成就档案、可选 NFT |
| 安全有底线 | 不因治愈风格弱化风险 | 风险章节严肃模式 |

### 1.5 对外表达

> **在 Monad 像素农场种下知识：学习让种子发芽，理解让它开花，真正掌握以后，收获属于自己的 Web3 成长记录。**

## 2. 产品目标与非目标

### 2.1 MVP 目标

- 用户注册后能够立即开启 Web3 通识课程。
- 用户能够完整体验一门课程的种子成长闭环。
- 三门课程按照前置条件自动解锁。
- 每门课程包含 3 个理论章节、3 组章节挑战和 1 次最终验证。
- 用户答错后能够理解原因并立即继续。
- Agent 能解释当前知识、辅助复习并执行标准化最终提问。
- 用户能够选择 Agent 对话或结课小测完成最终验证。
- 用户完成课程后获得果实、平台成就和 NFT 领取资格。
- 用户刷新或重新登录后能够恢复学习和农场状态。
- 系统管理员能够发现并修复平台状态不同步。
- 现场演示能够在 3～5 分钟内完成一门课程闭环。

### 2.2 MVP 非目标

- 不接入 Moss。
- 不实现 DeFi Swap、质押或沙盘余额。
- 不设置运营角色和课程运营后台。
- 不提供可视化课程编辑器和题库编辑器。
- 不做教师批改、周度作业和作品集。
- 不做排行榜、计时比赛、连续签到和社交关系。
- 不做自由种田、浇水、施肥、天气、季节、体力和真实时间生长。
- 不做钓鱼、小屋装饰、多人农场和交易市场。
- 不恢复修复温室主线。
- 不让 NFT 影响课程通过、等级和下一课程解锁。
- 不让系统管理员代替用户学习、答题、签名或领取 NFT。

## 3. 角色与权限

### 3.1 用户

用户能够：

- 注册、登录和退出。
- 查看和编辑自己的基础资料。
- 开启已解锁课程。
- 获得、查看和播种课程种子。
- 阅读理论章节和知识卡。
- 完成章节挑战并查看解释。
- 在允许的入口使用 Agent。
- 选择 Agent 对话或结课小测完成最终验证。
- 查看土地、作物成长和课程状态。
- 主动收获果实与平台成就。
- 查看学习档案、错题记录和成长记录。
- 连接自己的钱包并主动领取 NFT。

用户不能：

- 查看其他用户的资料和学习记录。
- 修改经验、课程结果、作物状态和成就。
- 跳过前置课程或成长阶段。
- 读取系统标准答案和 Agent 判定配置。
- 让 Agent 直接提交正式答案。
- 让管理员替自己完成钱包签名。

### 3.2 系统管理员

系统管理员能够：

- 登录稳定性管理面板。
- 查看 Web、登录、数据库、Agent、Monad RPC 和 NFT 服务状态。
- 查看异常用户、失败任务和脱敏错误日志。
- 开启维护模式或暂停故障入口。
- 修复课程、种子、土地、作物、经验、成就和 NFT 状态不同步。
- 重新读取链上回执并同步平台状态。
- 查看全部管理员操作记录。

系统管理员不能：

- 日常编辑课程、题目和标准答案。
- 替普通用户完成章节挑战或最终验证。
- 把错误答案修改为正确。
- 伪造学习完成记录、钱包签名和交易哈希。
- 访问私钥、助记词和完整敏感数据。
- 向正常用户手工发放不符合规则的奖励。

### 3.3 Agent 服务边界

Agent 可以读取：

- 已发布课程内容与知识卡。
- 当前用户正在学习的课程和章节。
- 用户主动提交的问题。
- 最终验证的固定问题、知识要点、等价表达和危险表达。

Agent 可以执行：

- 解释概念。
- 使用生活化类比。
- 根据错题提供提示。
- 推荐复习章节。
- 生成不计分练习。
- 进行标准化最终提问、追问和解释。

Agent 不能：

- 读取私钥、助记词和钱包授权。
- 获取其他用户数据。
- 在正式小测中直接给出答案。
- 修改课程、经验、作物、成就和 NFT 状态。
- 代替用户提交答案、连接钱包或签名。
- 提供收益承诺、价格预测或投资结论。

## 4. 核心学习成长流程

### 4.1 单门课程完整流程

```text
课程解锁
→ 用户开启课程
→ 系统发放知识种子
→ 用户开荒并播种
→ 学习 3 个理论章节
→ 获得经验，种子发芽
→ 完成 3 组章节挑战
→ 作物开花
→ 选择 Agent 对话或结课小测
→ 最终验证通过，作物结果
→ 用户主动收获
→ 获得果实、平台成就、NFT 资格
→ 解锁下一门课程
```

### 4.2 成长阶段映射

| 课程阶段 | 用户动作 | 农场反馈 | 用户获得 | 系统验证 |
|---|---|---|---|---|
| 可以开启 | 点击开启课程 | 种子进入背包 | 课程种子 | 课程满足前置条件 |
| 准备学习 | 开荒并播种 | 种子入土 | 学习任务 | 种子归属与土地可用 |
| 理论完成 | 完成全部理论 | 发芽动画 | 章节 EXP | 3 个章节均已读完 |
| 挑战完成 | 每章题目全部正确 | 开花动画 | 挑战 EXP | 3 组挑战均通过 |
| 最终验证通过 | Agent 或小测通过 | 结果动画 | 收获资格 | 固定判定规则通过 |
| 课程完成 | 点击收获 | 果实进入仓库 | 果实、成就、NFT 资格 | 收获事件成功且幂等 |

### 4.3 不允许的状态跳跃

- 未开启课程不能获得种子。
- 未获得种子不能播种。
- 未播种可以阅读课程介绍，但不能进入正式成长计分。
- 未完成全部理论不能触发发芽。
- 未完成全部章节挑战不能触发开花。
- 未完成最终验证不能触发结果。
- 未结果不能收获。
- 未收获不能解锁下一课程。
- NFT 成功与否不能改变课程完成状态。

### 4.4 断点恢复

- 章节阅读完成后立即保存。
- 每次答题提交后保存本次结果，但错误答案不覆盖已通过状态。
- Agent 每通过一道标准问题即保存单题状态。
- 小测提交后保存得分、错误项和重试次数。
- 每次成长动画开始前先提交业务状态，动画失败不回滚学习结果。
- 页面刷新后从最近一次有效业务状态恢复，不重复发放奖励。

## 5. 课程路线与课程内容

### 5.1 解锁顺序

```text
Web3 通识
→ Monad 基础
→ 智能合约
```

| 顺序 | 课程 | 种子 | MVP 章节数 | 解锁条件 |
|---|---|---|---:|---|
| 1 | Web3 通识 | 种子 1 | 3 | 注册完成 |
| 2 | Monad 基础 | 种子 2 | 3 | 收获 Web3 通识作物 |
| 3 | 智能合约 | 种子 3 | 3 | 收获 Monad 基础作物 |

### 5.2 Web3 通识

**学习目标**：理解账户、钱包、交易和基础安全，能够判断常见风险。

| 章节 | 主题 | 理论重点 | 章节挑战 | 难度角色 |
|---|---|---|---|---|
| 1 | 区块链、账户与地址 | 公开数据、地址、账户 | 判断题 ×1 | 认识/破冰 |
| 2 | 读取、签名与交易 | 读写差异、交易步骤、Gas | 两项选择 ×1 + 排序 ×1 | 熟练/巩固 |
| 3 | 私钥、助记词与签名风险 | 不能分享的信息、危险请求 | 风险场景判断 ×2 | 认真收尾 |

最终验证要点：

- 能解释地址与私钥的区别。
- 能说明读取公开余额为什么不需要签名。
- 能说出签名前需要检查的内容。

### 5.3 Monad 基础

**学习目标**：理解 Monad 网络的基本使用方式，能够读取和识别公开链上状态。

| 章节 | 主题 | 理论重点 | 章节挑战 | 难度角色 |
|---|---|---|---|---|
| 1 | Monad 与 EVM | 网络定位、EVM 兼容含义 | 判断题 ×1 | 认识/破冰 |
| 2 | RPC、区块与浏览器 | 网络、区块高度、交易查询 | 两项选择 ×1 + 排序 ×1 | 熟练/巩固 |
| 3 | 测试环境与资产安全 | 网络核对、测试资产、交互风险 | 风险场景判断 ×2 | 认真收尾 |

实践要求：

- 使用公开读取展示网络、区块高度或交易状态。
- 读取操作不要求钱包签名。
- UI 明确标注公开链上数据与平台教学数据的区别。

最终验证要点：

- 能解释钱包账户与网络的关系。
- 能说明如何在区块浏览器中查找交易。
- 能区分测试环境练习和真实资产操作。

### 5.4 智能合约

**学习目标**：理解智能合约状态、函数、ABI、事件和交易回执。

| 章节 | 主题 | 理论重点 | 章节挑战 | 难度角色 |
|---|---|---|---|---|
| 1 | 合约、状态与函数 | 合约是什么、状态如何变化 | 判断题 ×1 | 认识/破冰 |
| 2 | 读取、写入与 ABI | 函数类型、调用参数、签名 | 两项选择 ×1 + 排序 ×1 | 熟练/巩固 |
| 3 | 回执、事件与权限风险 | 成功判断、授权、陌生合约 | 风险场景判断 ×2 | 认真收尾 |

实践要求：

- 至少完成一次测试网合约公开读取。
- 用户能够看到读取目标、返回值和解释。
- 若加入写入实践，必须单独评审，不纳入 v3.5 默认范围。

最终验证要点：

- 能解释读取函数和写入函数的区别。
- 能说明 ABI 的作用。
- 能通过回执判断交易是否成功。

## 6. 标准课程结构

### 6.1 每门课程固定组成

- 课程名称、学习目标和预计时间。
- 前置课程与解锁条件。
- 对应种子、作物和课程成就。
- 3 个理论章节。
- 每章 1 张知识卡。
- 每章 1 组章节挑战。
- 每章 Agent 学习入口。
- 1 组 Agent 最终验证题。
- 1 套结课小测。
- 1 个收获结算页面。
- 1 个 NFT 领取资格。

### 6.2 理论章节模板

每章包含：

- 一句“学完你会……”的章节目标。
- 200～500 字正文。
- 1～3 个关键术语。
- 一个贴近钱包或链上场景的例子。
- 一个风险或注意事项。
- 一张总结知识卡。
- 一个“聊聊这个概念”Agent 入口。
- 一个“开始本章挑战”按钮。

### 6.3 知识卡模板

知识卡固定回答：

1. 这个概念是什么。
2. 为什么需要知道。
3. 用户实际会看到什么。
4. 哪些动作会改变资产或状态。
5. 操作前需要检查什么。

知识卡入口：

- 理论章节末尾。
- 章节挑战答错提示。
- Agent 对话引用。
- 个人学习档案。
- 最终验证前复习页。

## 7. 难度曲线

### 7.1 完整课程曲线

当课程扩展为 6 章时，统一使用：

```text
认识/破冰
→ 上手/引入
→ 熟练/巩固
→ 需要思考/小高峰
→ 放松/回落
→ 认真收尾/安全考验
```

### 7.2 MVP 三章曲线

MVP 每门课程固定使用：

```text
认识/破冰
→ 熟练/巩固
→ 认真收尾/风险判断
```

难度规则：

- 第 1 章只使用 1 道判断题，建立首次成功体验。
- 第 2 章加入两项选择或简单排序，检查概念关系。
- 第 3 章使用风险场景判断，必须明确指出安全后果。
- 不通过晦涩措辞制造难度。
- 不把长阅读量当作难度。
- 不使用倒计时、扣分和失败次数限制。

## 8. 章节挑战

### 8.1 题型

MVP 只使用：

- 判断题。
- 两项选择题。
- 简单步骤排序。
- 风险场景判断。

### 8.2 通过规则

- 每章 1～2 题。
- 每章必须全部正确。
- 可以不限次数重试。
- 重试不清空理论进度和其他已完成章节。
- 一次性全部正确获得少量额外 EXP。
- 额外 EXP 只发放一次，不因重复挑战累积。

### 8.3 答错反馈流程

1. 在题目下方显示行内反馈，不打开全屏弹窗。
2. 用一句话指出遗漏或误解，不只显示“错误”。
3. 展示对应知识卡入口“换个角度再看看”。
4. 展示 Agent 入口“聊聊这题”。
5. 提供“再试一次”按钮。
6. 保留本章之前的全部有效进度。

### 8.4 一般知识的反馈语气

允许使用：

- “这题有点绕，我们再看一眼。”
- “已经很接近了，再确认一下读取和签名的区别。”
- “换个角度看看这个知识卡，再试一次。”

不使用：

- “你失败了。”
- “能力不足。”
- “本关作废。”
- 纯红色大面积警告。
- 惩罚性音效和抖动动画。

### 8.5 安全知识的严肃模式

适用内容：

- 私钥和助记词。
- 钱包签名。
- Token 授权。
- 网络与资产核对。
- 陌生合约和钓鱼链接。

表达要求：

- 明确说明风险和可能后果。
- 使用警示图标、橙色或红色辅助状态，但不能只依赖颜色。
- 不使用玩笑、卖萌和模糊表达。
- Agent 引导统一为：“这一步涉及账户或资产安全，我陪你认真确认一遍。”
- 用户没有明确识别危险点时不能通过。

### 8.6 正向反馈

| 节点 | 用户可见反馈 | 系统动作 |
|---|---|---|
| 单题正确 | 叶片轻微生长，不弹出大结果页 | 保存单题结果 |
| 整章通过 | “种子又长高了一点” | 保存章节通过 |
| 首次全对 | “一次就理解了” | 发放一次额外 EXP |
| 全部章节通过 | 开花动画 | 解锁最终验证 |

## 9. 最终验证

### 9.1 入口设计

章节挑战全部完成后，页面显示：

> **最后确认一下你的收获：可以和学习助手聊一聊，也可以直接完成结课小测。两种方式都能完成课程。**

入口顺序：

1. **和 Agent 聊聊**：默认推荐。
2. **直接完成小测**：平等备选。

用户可以在两种方式之间切换，不丢失课程与章节进度。

### 9.2 Agent 标准化提问

每门课程固定配置 3 道情境问题。每道问题包含：

- 问题文本。
- 必须出现的知识要点。
- 允许的等价表达。
- 错误或危险表达。
- 第一次提示。
- 第二次提示。
- 单题通过条件。

判定规则：

- Agent 负责提问、追问和解释。
- 系统依据已配置知识要点记录结果。
- 回答缺少要点时先追问，不直接判定失败。
- 每题最多提供两次提示。
- 3 题全部通过后完成最终验证。
- Agent 服务异常或超时后显示“切换到结课小测”。
- 已通过的 Agent 单题在同一验证会话恢复时保留。

### 9.3 结课小测

- 每门课程固定 5 题。
- 使用判断题和两项选择题。
- 必须全部正确。
- 提交后显示每道题的解释。
- 允许不限次数重试。
- 不设置分数排名和限时。
- 用户可以随时改用 Agent 对话。

### 9.4 验证结果记录

| 完成方式 | 学习档案标记 | 对奖励的影响 |
|---|---|---|
| Agent 提问通过 | 对话验证 | 无额外稀缺性 |
| 结课小测通过 | 小测验证 | 无额外稀缺性 |
| 后续又完成另一方式 | 双重验证 | 只增加档案记录，不重复奖励 |

## 10. Agent 学习助手

### 10.1 使用入口

- 理论章节：“聊聊这个概念”。
- 知识卡：“换一种方式解释”。
- 答错反馈：“聊聊这题”。
- 复习页：“帮我梳理这一章”。
- 最终验证：“和 Agent 聊聊”。

### 10.2 回答层级

Agent 回答遵循三层结构：

1. **先回答当前问题**：使用 1～3 句话给出直接解释。
2. **再给一个例子**：优先使用钱包、交易或农场类比。
3. **最后确认理解**：给出一个不计分的小问题，用户可以跳过。

### 10.3 Agent 语气

- 友好、直接，不幼稚化用户。
- 不使用夸张吹捧。
- 不把错误归因于用户能力。
- 一般概念可以使用轻松类比。
- 安全相关问题必须切换严肃模式。
- 不把不确定信息表述为事实。

### 10.4 Agent 故障降级

当 Agent 不可用：

- 理论章节和知识卡继续可用。
- 章节挑战继续可用。
- 最终验证自动突出结课小测入口。
- 页面说明当前服务状态和已保存进度。
- 系统管理员面板产生 Agent 服务异常记录。

## 11. 种子、土地与作物

### 11.1 种子获取

课程满足条件后，用户点击“开启课程”，系统依次：

1. 创建课程进度。
2. 发放对应种子。
3. 将种子加入背包。
4. 解锁一块土地。
5. 引导用户前往开荒和播种。

同一用户、同一课程只能正常发放一次种子。

### 11.2 土地状态

```text
未解锁
→ 未开荒
→ 已开荒
→ 空闲
→ 已播种
→ 可以收获
→ 已收获
```

### 11.3 作物状态

```text
无作物
→ 种子入土
→ 发芽
→ 开花
→ 结果
→ 已收获
```

### 11.4 MVP 交互

- 选择未开荒土地。
- 点击开荒。
- 选择当前课程种子。
- 点击播种。
- 根据学习事件播放成长动画。
- 结果后由用户主动点击收获。

不加入浇水、施肥、时间等待、天气、体力、属性和重复收割。

### 11.5 动画与业务状态关系

- 业务状态先保存，动画后播放。
- 动画播放失败不回滚学习结果。
- 用户开启“减少动态效果”后改为静态状态切换。
- 发芽、开花、结果动画均提供文字说明。
- 结果动画停留 3～5 秒，然后进入收获结算。

## 12. 经验、等级、成就与 NFT

### 12.1 EXP 规则

EXP 只代表学习进度，不是货币。

| 行为 | EXP | 幂等规则 |
|---|---:|---|
| 完成理论章节 | 10 | 每章一次 |
| 完成章节挑战 | 20 | 每章一次 |
| 章节首次全部答对 | 5 | 每章一次 |
| 完成 Agent 最终验证 | 50 | 每门课程一次 |
| 完成结课小测 | 50 | 与 Agent 奖励不叠加 |
| 收获课程作物 | 100 | 每门课程一次 |

### 12.2 学习等级

| 等级 | 名称 | 解锁方式 |
|---|---|---|
| Lv.1 | 初来乍到 | 注册完成 |
| Lv.2 | Web3 学徒 | 收获通识作物 |
| Lv.3 | Monad 探索者 | 收获 Monad 作物 |
| Lv.4 | 合约建造师 | 收获智能合约作物 |

### 12.3 成就双层表达

系统记录使用明确结果名称：

- Web3 通识完成。
- Monad 基础完成。
- 智能合约完成。
- 三门课程完成。

用户界面使用纪念式名称与描述：

- 成就名称和对应作物、美术一起确定。
- 描述强调“种下、陪伴成长、完成收获”。
- 成就详情同时展示完成课程、完成日期和验证方式。
- 纪念式文案不能隐藏真实完成条件。

### 12.4 NFT 定位

NFT 是可选的链上学习纪念，同时记录课程完成事实。它：

- 不是课程通过条件。
- 不具有收益承诺。
- 不影响经验、等级和下一课程解锁。
- 不因选择 Agent 或小测形成价值差异。
- 可以稍后领取。

### 12.5 NFT 流程

1. 用户通过最终验证。
2. 作物结果。
3. 用户点击收获。
4. 平台发放果实与成就。
5. 系统生成 NFT 领取资格。
6. 用户主动选择领取。
7. 用户连接钱包。
8. 页面展示网络、内容和可能的 Gas。
9. 用户确认钱包请求。
10. 系统等待并验证真实回执。
11. 成功后进入学习档案。

### 12.6 NFT 失败处理

- 用户拒绝签名：保留领取资格。
- RPC 不可用：暂停入口并允许稍后重试。
- 交易失败：保留领取资格和失败记录。
- 链上成功但平台未同步：管理员重新读取回执。
- 任何 NFT 失败都不能回滚课程、果实和平台成就。

## 13. 学完后的 MVP 留存

MVP 不承诺自由经营，但必须让完成课程的用户仍有可用内容：

- 回到农场查看已经收获的作物与土地。
- 在成就档案查看课程、日期、验证方式和 NFT。
- 回看知识卡。
- 回看错题与解释。
- 使用 Agent 复习已完成课程。
- 补做另一种最终验证，形成双重验证记录，但不重复发奖。

后续版本可以加入自由种田、钓鱼和小屋装饰；在功能真正进入开发范围前，不作为当前核心宣传承诺。

## 16. 系统管理员面板

### 16.1 面板目标

系统管理员面板只回答：

1. 平台是否正常。
2. 哪个服务、用户或任务状态异常。
3. 管理员如何安全修复并留下记录。

### 16.2 系统状态总览

展示：

- Web 服务、登录服务和数据库状态。
- Agent 服务状态、成功率、平均响应时间和失败数。
- Monad RPC 和 NFT 服务状态。
- 最近错误数和失败任务数。
- 当前维护模式与暂停模块。

操作：

- 开启或关闭维护模式。
- 暂停故障模块入口。
- 恢复已修复模块。
- 查看错误详情。

### 16.3 学习状态异常

展示：

- 用户标识和当前课程。
- 课程、章节、挑战和最终验证状态。
- 种子、土地、作物、EXP、成就和 NFT 状态。
- 最近一次有效事件和异常原因。

允许修复：

- 课程开启但种子未发放。
- 理论完成但作物未发芽。
- 挑战完成但作物未开花。
- 验证通过但作物未结果。
- 已收获但成就或 EXP 未发放。
- NFT 链上成功但平台状态未更新。

修复约束：

- 必须填写原因。
- 必须记录管理员身份。
- 必须保存修改前后状态。
- 不能修改正常答案或伪造验证通过。
- 不能伪造钱包签名、交易哈希和链上成功。

### 16.4 Agent 服务

展示：

- 在线状态、请求量、成功率和响应时间。
- 超时数、安全策略拦截数和最终验证异常数。
- 脱敏错误日志。

操作：

- 开启或关闭 Agent 入口。
- 清理异常会话。
- 切换维护状态。

### 16.5 Monad 与 NFT 服务

展示：

- RPC 状态。
- NFT 领取服务状态。
- 待确认、成功、失败和回执验证失败记录。

操作：

- 暂停 NFT 领取入口。
- 重新读取交易回执。
- 同步平台 NFT 状态。
- 恢复 NFT 服务。

| Agent 会话 | 课程、问题、提示、单题结果 |
| 管理员日志 | 操作人、原因、修改前后状态 |

数据原则：

- 学习、农场与奖励状态必须可恢复。
- 钱包不是平台账号的唯一身份。
- 不保存私钥、助记词和签名原文。
- Agent 对话只保存完成学习和故障排查需要的内容。
- 管理员修复必须具备完整审计记录。
- NFT 链上状态以真实回执为依据。

## 20. UI 与视觉需求

### 20.1 总体画面

- 原创 16-bit 治愈系像素风。
- 保留 Monad 知识库、学习工坊、种子小铺、未开荒土地和成就入口。
- 主地图承担导航和成长反馈，课程正文和长文本使用 DOM/CSS 排版。
- 中文文本不得嵌入 AI 生成图片。
- 像素素材使用整数倍缩放与 `image-rendering: pixelated`。

### 20.2 农场首页

必须展示：

- 当前等级与 EXP。
- 三门课程的解锁和完成状态。
- 当前土地与作物成长状态。
- 下一步明确行动。
- 最近一次成长记录。
- 成就档案入口。

第一主按钮只出现一个，根据状态依次为：

- 开启课程。
- 前往播种。
- 继续学习。
- 继续挑战。
- 开始最终验证。
- 收获。

### 20.3 课程页面

页面结构：

1. 课程标题、学习目标和对应种子。
2. 线性小径式章节地图。
3. 当前章节正文与知识卡。
4. Agent 入口。
5. 章节挑战入口。
6. 作物成长缩略状态。

章节节点状态：

- 未解锁：锁图标 + 条件文字。
- 当前：高亮边框 + “正在这里”。
- 已读完：书本完成图标。
- 挑战完成：植物成长图标。
- 安全章节：盾牌图标 + 严肃提示。

### 20.4 挑战页面

必须展示：

- 当前章节和题目序号。
- 题干、选项或排序区域。
- 轻量进度，不使用倒计时。
- 提交按钮。
- 行内反馈区域。
- 知识卡与 Agent 入口。
- “再试一次”动作。

### 20.5 最终验证页面

- Agent 入口放在首位并标记“推荐”。
- 小测入口说明“也可以直接确认”。
- 两种方式明确写出结果相同。
- Agent 故障时不隐藏小测入口。
- 切换方式前说明已保存进度。

### 20.6 成长动画

| 节点 | 动画 | 文案方向 |
|---|---|---|
| 获得种子 | 种子落入背包 | “这颗种子对应你的第一门课程” |
| 发芽 | 土壤破开、嫩芽出现 | “你已经认识了这些基础概念” |
| 开花 | 花苞展开 | “知识已经连成一条完整路径” |
| 结果 | 果实生长，停留 3～5 秒 | “你已经完成最后的理解确认” |
| 收获 | 果实进入档案 | “这段学习已经被好好保存” |

### 20.7 状态视觉

| 状态 | 主色 | 图标/文字要求 |
|---|---|---|
| 已解锁 | 紫色 | 发光边框 + 已解锁 |
| 学习中 | 蓝色 | 书本 + 当前章节 |
| 发芽/开花 | 绿色 | 植物阶段 + 明确文字 |
| 可以收获 | 金色 | 果实 + 可以收获 |
| 一般答错 | 暖橙 | 提示图标 + 原因 + 重试 |
| 安全风险 | 红色/橙色 | 盾牌或警告 + 明确后果 |
| 服务维护 | 橙色 | 工具图标 + 替代路径 |

状态不能只依赖颜色。

### 20.8 关键微文案

| 场景 | 文案 |
|---|---|
| 开启课程 | “带上这颗种子，去认识第一块知识土地。” |
| 一般答错 | “这题有点绕，我们再看一眼。” |
| 章节完成 | “种子又长高了一点。” |
| 首次全对 | “一次就理解了。” |
| 安全章节开始 | “这一步涉及账户或资产安全，我陪你认真确认一遍。” |
| Agent 验证入口 | “和学习助手聊聊，确认你已经理解。” |
| 小测入口 | “也可以直接完成结课小测。” |
| 结果 | “你的知识种子已经结出果实。” |
| 收获 | “这段学习已经被保存到你的农场档案。” |

## 21. 错误与恢复

用户端错误必须回答：

1. 发生了什么。
2. 已完成进度是否保留。
3. 下一步可以做什么。

| 异常 | 用户结果 | 恢复动作 |
|---|---|---|
| 登录失败 | 不进入账户 | 重试或检查登录信息 |
| 课程加载失败 | 保留进度 | 重新加载 |
| 答案提交超时 | 不改变挑战状态 | 重新提交 |
| Agent 不可用 | 课程继续可用 | 切换结课小测 |
| Agent 会话中断 | 保留已通过单题 | 恢复或切换小测 |
| EXP 漏发 | 不影响课程状态 | 管理员修复 |
| 种子漏发 | 暂不能播种 | 管理员重新执行发放 |
| 作物不同步 | 显示最近有效状态 | 管理员修复 |
| NFT 签名拒绝 | 成就不受影响 | 稍后领取 |
| NFT 交易失败 | 保留资格 | 重试 |
| RPC 不可用 | 暂停 NFT 入口 | 稍后重试 |

## 22. 安全与隐私

- 平台不保存私钥和助记词。
- 正式小测期间 Agent 不提供当前题目答案。
- Agent 不提供投资建议和收益承诺。
- NFT 页面明确显示网络、操作内容和可能的 Gas。
- 钱包签名只能由用户主动发起。
- 系统管理员不能伪造链上成功。
- 用户数据默认仅本人可见。
- 管理员界面使用脱敏用户信息和钱包地址。
- 管理员操作全部记录。
- 课程内容引用链上信息时必须区分教学解释、公开读取结果和链上交易结果。

## 25. 功能验收

### 25.1 课程与种子

- [ ] 注册后 Web3 通识为可以开启。
- [ ] 点击开启课程后只发放一次种子。
- [ ] 后续课程在前置作物收获前不能开启。
- [ ] 用户必须主动开荒和播种。
- [ ] 刷新后种子、土地和课程状态保留。

### 25.2 理论与成长

- [ ] 每门课程固定包含 3 个 MVP 章节。
- [ ] 全部理论完成后发芽并发放 EXP。
- [ ] 全部章节挑战通过后开花。
- [ ] Agent 或小测通过后结果。
- [ ] 未结果不能收获。
- [ ] 收获后发放果实、成就和 NFT 资格。
- [ ] 收获后解锁下一课程。

### 25.3 章节挑战

- [ ] 第 1 章为认识/破冰难度。
- [ ] 第 2 章包含概念关系或步骤排序。
- [ ] 第 3 章包含风险场景判断。
- [ ] 每章必须全部正确。
- [ ] 答错使用行内反馈并说明原因。
- [ ] 答错后提供知识卡、Agent 和重试入口。
- [ ] 重试不清空其他有效进度。
- [ ] 首次全对奖励只发放一次。

### 25.4 Agent 与小测

- [ ] Agent 能解释当前课程和知识卡。
- [ ] Agent 默认作为推荐最终验证入口。
- [ ] Agent 标准化提问使用固定知识要点判定。
- [ ] 每门课程 Agent 最终验证包含 3 道问题。
- [ ] 结课小测固定 5 题且必须全部正确。
- [ ] 正式小测中 Agent 不直接提供答案。
- [ ] Agent 故障时可以切换小测。
- [ ] 两种验证方式的课程奖励一致。

### 25.5 体验语言

- [ ] 一般答错不使用惩罚性文案和大面积红色。
- [ ] 安全章节明确切换为严肃表达。
- [ ] 私钥、签名和授权风险必须写明可能后果。
- [ ] 结果动画停留 3～5 秒。
- [ ] 成就页面同时显示纪念表达和真实完成条件。

### 25.6 NFT

- [ ] NFT 为用户主动领取。
- [ ] NFT 失败不影响课程和平台成就。
- [ ] 同一资格不能成功领取两次。
- [ ] 系统管理员不能替用户签名。
- [ ] 链上成功以真实回执为依据。

### 25.7 系统管理员

- [ ] 面板显示关键服务状态。
- [ ] 管理员可以暂停 Agent 和 NFT 故障入口。
- [ ] 管理员可以修复状态不同步。
- [ ] 每次修复必须填写原因。
- [ ] 修改前后状态进入审计日志。
- [ ] 管理员不能修改正常答案或伪造验证通过。

## 26. 非功能需求

### 26.1 性能

- 主要操作点击后 100 毫秒内显示反馈。
- 课程页面在正常网络下 2.5 秒内可交互。
- Agent 请求必须具备等待、超时、重试和降级状态。
- 管理员状态面板不得无限加载。

### 26.2 可用性

- Agent 故障不阻断结课。
- NFT 故障不阻断课程。
- 刷新不丢失学习进度。
- 同一完成事件重复提交不重复发放奖励。
- 动画失败不影响业务状态。

### 26.3 可访问性

- 按钮支持键盘操作。
- 状态不只使用颜色。
- 作物动画提供文字状态。
- 对话框具备标题、关闭和焦点管理。
- 支持减少动态效果。
- 安全警告使用图标、标题、文字三重表达。

## 29. v3.0 到 v3.5 的变化

| 领域 | v3.0 | v3.5 |
|---|---|---|

| Moss | 不在主流程 | 明确不接入 |
