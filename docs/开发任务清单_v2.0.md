## 阶段一：用户系统（P0）

### 1.1 账号注册
- [ ] **API:** POST /api/users/register
  - 接收 username、avatarUrl（可选）
  - 生成 userId（UUID），创建用户记录
  - 返回用户信息
- [ ] **幂等:** username 唯一约束，重复注册返回 409

### 1.2 登录/退出
- [ ] **API:** POST /api/auth/login
  - 简单 Token 认证（暂不涉及密码，可用 userId 直接登录）
- [ ] **API:** POST /api/auth/logout
- [ ] **中间件:** 身份验证中间件，从请求头提取 Token 校验
- [ ] **前端:** 登录页、401 拦截跳转

### 1.3 个人资料编辑
- [ ] **API:** PUT /api/users
  - 修改 username、avatarUrl
- [ ] **权限:** 只能修改自己的资料

### 1.4 权限控制
- [ ] **users 表增加 role 字段**（`"user" | "admin"`），管理员是 user 的一种类型
- [ ] **中间件:** 接口级权限校验，区分普通用户和管理员操作
- [ ] **路由守卫（前端）:** 管理员页面权限判断

## 阶段三：审核系统（P0）

### 3.1 数据库表
- [ ] `audit_sessions` — 审核会话
  - id, user_id, course_id, status, items_json, audit_type, started_at, completed_at
  - audit_type: `"manual" | "agent"` — 审核方式
  - status: `"pending" | "in_progress" | "passed" | "failed"`

### 3.2 审核方式配置
- [ ] 配置项：Agent 审核开关（环境变量 `AGENT_REVIEW_ENABLED=true/false`）
- [ ] 开启时使用 Agent 审核，关闭时管理员人工审核
- [ ] **API:** GET /api/admin/audit-config — 查看当前审核配置

### 3.3 管理员人工审核
- [ ] **API:** GET /api/admin/audit/pending — 待审核列表
- [ ] **API:** POST /api/admin/audit/:id/approve — 人工审核通过
- [ ] **API:** POST /api/admin/audit/:id/reject — 人工审核拒绝

### 3.4 Agent 审核
- [ ] **API:** POST /api/audit/start — 创建审核会话（Agent 模式）
- [ ] **API:** POST /api/audit/submit — 提交审核项（逐条判定）
- [ ] **API:** GET /api/audit/status — 查询审核状态
- [ ] Agent 健康检查与超时检测
- [ ] Agent 不可用时降级为人工审核

### 3.5 验证方式切换
- [ ] **API:** POST /api/verification/switch
  - 在审核（Agent/人工）和结课小测之间切换
  - 不丢失已完成进度
- [ ] 切换状态记录

## 数据库变更汇总

| 表名 | 操作 | 说明 |
|------|------|------|
| `users` | **修改** | 增加 `role` 字段（`"user" \| "admin"`），删除 `admin_users` 表 |
| `audit_sessions` | **新增** | 审核会话（含 audit_type 标识人工/Agent） |

**已删除的表：** audit_rules、system_config、admin_users（合并到 users）

## 设计要点说明

| 要点 | 方案 |
|------|------|
| 管理员身份 | users 表 `role` 字段区分，不做独立表 |
| 审核方式 | 两种：人工审核（管理员操作）和 Agent 审核 |
| Agent 开关 | `system_config` 表 `agent_review_enabled` 键控制，管理端页面按钮切换 |
| 审核规则 | 不需要独立规则表，审核逻辑内置于代码中 |
| 系统配置 | 暂不需要，等后续迭代 |
