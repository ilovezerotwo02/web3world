# 四人任务分配

## 成员 1：产品与视觉

- 维护三关故事、NPC 文案、知识卡和演示讲稿。
- 维护 `design/screens/` 的八张页面基准图。
- 管理 `public/art/` 地图、人物、温室阶段与道具素材。
- 每次 UI 改动后检查 1440×900 画布、像素缩放和中文排版。

## 成员 2：前端与游戏体验

- 维护 `app/game/FarmGame.tsx` 和 `app/globals.css`。
- 负责 HUD、地图热点、任务控制台、动画、错误恢复和总结页。
- 页面只消费协议适配层返回的读取、报价、执行、验证结果，不拼装 ABI。
- 每合入一关便导出对应视觉截图并完成浏览器回归。

## 成员 3：Monad 与协议

- 维护 `app/lib/protocols.ts`。
- 负责 viem 读取、Kuru 报价/授权/Swap、aPriori 报价/质押。
- 保证完成条件同时包含成功回执和前后余额差。
- 合约字段、函数签名和地址只来自官方 ABI、SDK 源码或 Fork 实测结果。

## 成员 4：Moss 与质量

- 赛事 starter 到位后，先独立跑通 Fork 创建、锁块、资产预置、签名发送、Swap、质押和重置。
- 将实测 RPC 与会话生命周期接入现有适配层，不让页面感知 Moss 响应结构。
- 维护端到端测试、部署配置、失败场景清单和评委演示脚本。
- 重置沙盘时同步清除以会话 ID 和钱包地址为边界的本地进度。

## 协作顺序

1. 成员 4 证明 Moss 上两笔真实交易可执行。
2. 成员 3 把已验证调用封装成读取、报价、执行、验证四类结果。
3. 成员 2 接入当前关卡并完成端到端演示。
4. 成员 1 校正文案、视觉反馈与截图。
5. 每完成一关立即合并和演示，不等待三关全部完成。
